Кнопка ведёт на GitHub?
Вы на вкладке Pages — нужна Workers

Cloudflare поменял интерфейс: теперь создание называется «Create application», и по умолчанию открывается вкладка Pages (подключение GitHub). Нам она не нужна. Нужна соседняя вкладка Workers — это один клик. Ниже — точный путь и проверка готового реле.

Быстрое решение — 3 клика

  1. На странице, куда привела кнопка Create application, посмотрите наверх: там две вкладки — Pages и Workers.
  2. Нажмите вкладку Workers (GitHub-подключение исчезнет — так и должно быть).
  3. Выберите шаблон Hello World! (или «Start with Hello World»), задайте имя и нажмите Deploy.

Страница с GitHub — это вкладка Pages

Cloudflare предлагает два продукта на одной странице: Pages (сайты из GitHub) и Workers (маленькие программы-посредники). Нам нужен Workers. Вкладка Pages открылась по умолчанию — просто переключитесь.

  1. Поднимите взгляд к верху страницы — там переключатель Pages / Workers.
  2. Нажмите Workers.
  3. Появится выбор шаблона → нажмите Hello World! → «Create Worker» / «Deploy».

Пункт может называться по-другому

В разных версиях интерфейса нужный раздел зовут Workers & Pages, просто Workers или Compute (Workers). Ещё он может быть свёрнут в группу. Три способа найти:

  1. Ссылка напрямую — кнопка ниже, минуя меню целиком.
  2. Поиск по дашборду: нажмите Ctrl+K (или значок лупы сверху) и введите workers → выберите «Workers & Pages» / «Workers».
  3. Убедитесь, что вы на уровне аккаунта, а не внутри домена: нажмите логотип Cloudflare / «Account home» слева вверху.

Замените код и нажмите Deploy

  1. Кликните в область кода слева (файл worker.js).
  2. Выделите всё: Ctrl+A (на Mac ⌘A) → удалите Delete.
  3. Вставьте наш код: кнопка «Скопировать код» ниже → Ctrl+V / ⌘V.
  4. Нажмите Deploy справа вверху. Если спросит подтверждение — подтвердите.

const DEFAULT_ALLOWED = ["ai.starimg.ru"];
const CORS = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Methods": "GET, POST, OPTIONS",
  "Access-Control-Allow-Headers": "authorization, content-type, x-target-url, x-relay-key",
  "Access-Control-Max-Age": "86400",
};
export default {
  async fetch(req, env) {
    if (req.method === "OPTIONS") return new Response(null, { status: 204, headers: CORS });
    const url = new URL(req.url);
    const target = req.headers.get("x-target-url") || url.searchParams.get("target");
    const json = (obj, status) => new Response(JSON.stringify(obj), { status, headers: { ...CORS, "Content-Type": "application/json" } });
    if (!target) return json({ error: "Передайте целевой URL в заголовке x-target-url или ?target=" }, 400);
    let t;
    try { t = new URL(target); } catch { return json({ error: "Некорректный целевой URL" }, 400); }
    if (t.protocol !== "https:") return json({ error: "Разрешён только https" }, 403);
    const allowed = (env.ALLOWED_TARGETS || DEFAULT_ALLOWED.join(",")).split(",").map(s => s.trim()).filter(Boolean);
    if (allowed.length && !allowed.includes(t.hostname)) return json({ error: "Хост не в списке разрешённых: " + t.hostname }, 403);
    if (env.RELAY_SECRET && req.headers.get("x-relay-key") !== env.RELAY_SECRET) return json({ error: "Неверный секрет реле" }, 401);
    const headers = new Headers(req.headers);
    ["x-target-url", "x-relay-key", "host", "origin", "referer", "cf-connecting-ip", "cf-ray", "cf-visitor", "x-forwarded-for", "x-real-ip"].forEach(h => headers.delete(h));
    const resp = await fetch(t.toString(), {
      method: req.method,
      headers,
      body: ["GET", "HEAD"].includes(req.method) ? undefined : req.body,
      redirect: "follow",
    });
    const out = new Headers(resp.headers);
    Object.entries(CORS).forEach(([k, v]) => out.set(k, v));
    return new Response(resp.body, { status: resp.status, headers: out });
  },
};

Если что-то пошло не так

Значит, вы всё ещё в разделе Pages. Прямая ссылка на создание воркера: открыть. На открывшейся странице переключатель Pages/Workers находится в самом верху, над карточками шаблонов. Если его не видно — прокрутите страницу вверх до конца.
Обычно причина: 1) не подтверждена почта аккаунта — проверьте письмо от Cloudflare; 2) не задано имя воркера — впишите любое латиницей, например synapse-relay; 3) редактор не дал сохранить изменения — нажмите Ctrl+S внутри редактора, затем Deploy.
Воркер создан, но код не заменён. Откройте воркер → Edit code → Ctrl+A → Delete → вставьте наш код (кнопка копирования выше) → Deploy. После деплоя подождите 10–20 секунд и повторите проверку.
Три варианта: 1) адрес скопирован не полностью или с опечаткой — сверьте с адресом в дашборде; 2) деплой ещё не применился — подождите минуту; 3) ваш оператор блокирует домены workers.dev (бывает в РФ). Тогда привяжите свой домен: воркер → Settings → Domains & Routes → Add → Custom Domain. Проверить просто: откройте адрес реле в Safari — должен появиться текст про x-target-url.
Реле работает, но ключ отклонён продавцом. Скопируйте ключ заново целиком, без пробелов. Если задавали RELAY_SECRET в воркере — впишите тот же секрет в Синапсе («Секрет реле»). 403 с текстом «Хост не в списке разрешённых» означает, что в ALLOWED_TARGETS нет ai.starimg.ru — оставьте переменную пустой или добавьте хост.
Да, если продавец включит CORS-заголовки на сервере ai.starimg.ru — тогда Синапс заработает напрямую, без реле. Напишите ему: «Добавьте, пожалуйста, Access-Control-Allow-Origin и Allow-Headers: authorization, content-type, и ответ на OPTIONS». Пока он не включил — реле самый быстрый путь. Пользоваться Синапсом в демо-режиме (с настоящим поиском) можно и без всего этого.
Защитить реле паролем (необязательно)
Воркер → Settings → Variables → Add: имя RELAY_SECRET, значение — любой пароль → Deploy. В Синапсе в поле «Секрет реле» впишите тот же пароль. Без этого реле тоже работает, но пароль не даст посторонним гонять трафик через ваш воркер.
