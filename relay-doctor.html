Скорее всего, это не ошибка

Когда открываешь адрес воркера просто в браузере, он обязан ответить текстом {"error":"Передайте целевой URL…"} — это наш код так говорит «я жив, жду запрос от Синапса». Браузер показывает это как ошибку, но для реле это признак успеха. Настоящие проблемы выглядят иначе: «Hello World», «Error 1101» или страница не грузится. Сейчас проверим ваш адрес автоматически.

Живая диагностика

Страница сама отправит запрос на ваш воркер и расшифрует ответ. Ничего никуда не передаётся, кроме запроса к вашему реле.
Ключ хранится только в вашем браузере и уходит только на ваше реле.

Реле работает — переносим в Синапс

Осталось одно действие: записать адрес в настройки приложения. Кнопка сделает это сама (если страница открыта на том же сайте, где Синапс), либо скопирует адрес для ручной вставки.

Открыть Синапс Шаг 8 инструкции
В Синапсе проверьте: Настройки → Режим «Свой OpenAI-совместимый API», API Host https://ai.starimg.ru/v1, ваш ключ, модель, и поле CORS-реле = адрес вашего воркера. Включите тумблер «Поиск в интернете» — и задайте вопрос о свежих событиях.

Это не ошибка — это ваш работающий посредник

Наш код специально отвечает таким JSON, когда к нему обращаются «вручную», без цели. Он как бы говорит: «Я на месте, но мне не сказали, куда переслать запрос». Синапс всегда передаёт цель в заголовке x-target-url, поэтому у него всё будет работать.

Действие: нажмите «Записать адрес в Синапс» выше (или скопируйте адрес и вставьте в Настройки → CORS-реле). Больше в Cloudflare ничего делать не нужно.

«Hello World» = вы нажали Save, но не Deploy

В новом редакторе Cloudflare кнопка Save лишь сохраняет черновик. Чтобы код заработал на адресе воркера, нужно нажать Deploy (оранжевая кнопка справа вверху). Это самая частая причина «я вписал код, а не работает».

// после вставки нашего кода:
const DEFAULT_ALLOWED = ["ai.starimg.ru"];
const CORS = { … };
export default { async fetch(req, env) { … } };
// → нажмите оранжевую Deploy, подтвердите
  1. Откройте воркер → Edit code.
  2. Убедитесь, что в редакторе именно наш код (начинается с const DEFAULT_ALLOWED).
  3. Нажмите оранжевую Deploy справа вверху → подтвердите.
  4. Подождите 15–30 секунд и нажмите «Проверить ещё раз» выше.
Проверить, что опубликовалось: вкладка Deployments (или «Versions») на странице воркера — верхняя запись должна быть свежей, с пометкой активной.

Error 1101 = код вставлен повреждённым

Воркер падает при выполнении. Обычно это значит: код скопирован не полностью, скопирован сокращённый пример с картинки (там есть «…» — это не настоящий код), или при вставке что-то удалилось/задвоилось. Лечится чистой перевставкой:

  1. Скопируйте правильный код кнопкой ниже (или скачайте файл worker.js).
  2. В редакторе воркера кликните в код → Ctrl+A (⌘A на Mac) → Delete — поле должно стать пустым.
  3. Вставьте код целиком: Ctrl+V / ⌘V.
  4. Проверьте: первая строка const DEFAULT_ALLOWED = ["ai.starimg.ru"];, последняя — };. Никаких красных подчёркиваний быть не должно.
  5. Нажмите Deploy → подтвердите → подождите 20 секунд → «Проверить ещё раз».
Не копируйте код с картинок-примеров в инструкции — там сокращённые строки с «…» для наглядности. Настоящий код только в блоке ниже и в файле worker.js.

404 / «There is nothing here» — адрес или маршрут

  1. Сверьте адрес символ в символ с тем, что в дашборде: воркер → Overview / Triggers. Имя воркера и поддомен аккаунта (amicus0206) должны совпадать.
  2. Проверьте, что маршрут workers.dev включён: воркер → Settings → Domains & Routes → строка workers.dev должна быть активной (тумблер включён). Если выключена — включите.
  3. Убедитесь, что воркер не удалён и деплой прошёл (вкладка Deployments).
  4. Если адрес верный, но 404 не уходит — удалите маршрут workers.dev и добавьте заново, либо пересоздайте воркер с нашим кодом.

Не открывается — вероятно, блокировка workers.dev

У части операторов РФ домены *.workers.dev недоступны. Диагностика выше в этом случае покажет «не удалось соединиться». Проверка простая: откройте адрес реле с другой сети (мобильный интернет вместо Wi-Fi или наоборот). Если с другой сети открывается — дело в операторе.

  1. Воркер → Settings → Domains & Routes → Add → Custom Domain.
  2. Введите свой домен или поддомен (например relay.вашдомен.ru). Домен должен быть добавлен в Cloudflare (.free-план подходит).
  3. Дождитесь выпуска сертификата (обычно минуты), откройте новый адрес в Safari — должен появиться JSON про x-target-url.
  4. В Синапсе укажите новый адрес в поле «CORS-реле» вместо workers.dev.
Своего домена нет? Можно купить дешёвый (.ru ~200 ₽/год) или попросить продавца ключа включить CORS на сервере — тогда реле вообще не понадобится.

Другой ответ — читаем вместе

Нажмите «Проверить ещё раз» выше — диагностика покажет точный ответ вашего воркера и расшифрует его. Ориентиры:

✓{"error":"Передайте целевой URL…"}реле работает
!{"error":"Хост не в списке разрешённых…"}проверьте ALLOWED_TARGETS
!{"error":"Неверный секрет реле"}RELAY_SECRET не совпадает
✗Hello World! / Error 1101 / 404см. карточки выше
Если видите JSON с ошибкой про хост или секрет — это тоже наш код, значит деплой прошёл; осталось поправить переменные в Settings → Variables (или оставить их пустыми).
